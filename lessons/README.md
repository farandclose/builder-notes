# Lessons

Each lesson is one file about one thing I learned while building. It's short on purpose, so it's easy to read and easy to link to from a post.

## Naming

`YYYY-MM-short-title.md`, for example `2026-11-comments-never-reach-git.md`. The date is when I learned it, not when I wrote it up.

## Format

```
# A title that states the lesson

Project: which build it came from
When: month and year

**What I believed:** what I assumed going in.

**What happened:** what actually happened when it met real use. Keep it to the facts I saw myself.

**What I'd do now:** the change I made, or would make next time.

**Evidence (optional):** a link to the commit, PR, post or page it came from.
```

## Rules I keep to

- One learning per file. If it needs two, it's two lessons.
- Under about 300 words.
- Only what I saw myself. No claims I can't point back to.
- Nothing from my day job, and no private data about anyone.
- Every new lesson gets a line at the top of the Lessons list in the main README.
